Volatility symbols

Prepare matching symbols once, then focus on the evidence.

Windows: download for your image

Replace /cases/memory.img with your capture. Volatility obtains the matching PDB from Microsoft's public symbol server and converts it to its JSON symbol format. This setup needs internet access.

mkdir -p -- {{ download_root }}
vol -f /cases/memory.img -s {{ download_root }} windows.info.Info

After identification succeeds, install the downloaded tables in Volatility's default search path. This lets ordinary vol commands find them without -s. Installation requires sudo; analysis runs as your normal account.

Check the setup, then run your investigation:

vol -q --offline -f /cases/memory.img windows.info.Info
vol -q -f /cases/memory.img -r jsonl windows.cmdline.CmdLine --pid 1812

Use a PID from your process inventory. Repeat symbol onboarding for a different Windows build if its symbols are missing.

Offline symbol packs

The official symbol packs can be downloaded on a connected machine and transferred to SIFT. Keep the ZIP filenames and verify their hashes before installation. Packs cover selected builds, not every capture.

curl -fL --output windows.zip https://github.com/volatilityfoundation/volatility3-test-data/releases/download/v0.0.1/windows.zip
curl -fL --output SHA256SUMS https://raw.githubusercontent.com/volatilityfoundation/volatility3-test-data/refs/tags/v0.0.1/symbols/SHA256SUMS
sha256sum --check --ignore-missing SHA256SUMS
{% if symbol_root %}

Proceed only when windows.zip: OK is reported:

sudo install -m 644 -- windows.zip {{ quoted_root }}/windows.zip
{% endif %}

Other official packs: linux.zip · mac.zip. Substitute that filename in the download and install commands; the same checksum file covers all three. Leave the archives zipped. The first scan indexes new symbols and may take longer.

Linux and macOS: match the captured kernel 
vol -f /cases/memory.img banners.Banners

Match the entire kernel banner, including build details. Check the official packs and the community collection linked from Volatility's Linux tutorial. When no table matches, use the captured kernel's debug image with dwarf2json; an ordinary stripped kernel is insufficient. Follow the official symbol generation instructions.

With dwarf2json available and matching debug files in /cases/kernel/:

dwarf2json linux --elf /cases/kernel/vmlinux --system-map /cases/kernel/System.map > kernel.json
{% if symbol_root %}
sudo install -D -m 644 -- kernel.json {{ quoted_root }}/linux/kernel.json
vol -q --offline -f /cases/memory.img linux.pslist.PsList
{% endif %}

For macOS, generate with dwarf2json mac --macho /cases/kernel/kernel.debug > kernel.json and install under mac/. Use distinct filenames for different kernels. Successful Linux/macOS analysis still requires a matching capture and supported plugin.

SIFTed storage and permissions

SIFTed uses {{ managed_symbols }} for automatic downloads. The service account needs read, write and directory traversal access there. It also reads symbols from the installed Volatility search paths. It never needs sudo to analyze memory.

For another managed directory, configure SIFTED_VOLATILITY_SYMBOLS with a directory owned by the service account. Additional Linux/macOS symbol directories must be allowed by SIFTED_SYMBOL_ROOTS and selected in the plugin examiner. Explicitly selected directories remain in CLI examples.

Grant write access only to the chosen download directory; keep Volatility's program files administrator-owned. The commands above install readable symbol data without granting the app permission to change program code.
